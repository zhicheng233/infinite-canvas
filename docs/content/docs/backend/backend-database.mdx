# 后端数据库结构

## users 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uint | 主键 |
| tenant_id | uint | 当前固定为默认租户 |
| username | string(64) | 登录用户名，全局唯一；仅允许 1-64 位 ASCII 字母、数字、下划线和短横线，写入前去除首尾空白 |
| password_hash | string(256) | bcrypt 密码哈希 |
| display_name | string(64) | 显示名称 |
| avatar_url | string(512) | 头像 |
| role | enum(super_admin/tenant_admin/user) | 角色 |
| status | enum(active/inactive) | 状态 |

## credit_accounts 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uint | 主键 |
| tenant_id | uint | 租户 ID |
| user_id | uint | 用户 ID |
| balance | int | 当前积分余额 |
| total_earned | int | 累计收入 |
| total_spent | int | 累计支出 |

管理员增加、扣减或设定目标余额时，会在同一数据库事务内锁定目标账号，原子更新 `balance`、`total_earned`、`total_spent` 并写入一条 `adjust` 流水；任一步失败都会整体回滚。

## credit_transactions 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uint | 主键 |
| account_id | uint | 账户 ID |
| type | enum(earn/spend/refund/adjust) | 流水类型 |
| amount | int | 变动积分 |
| balance_before | int | 变动前余额 |
| balance_after | int | 变动后余额 |
| ref_type | string(50) | 业务来源，如 image/video/audio/recharge |
| ref_id | string(100) | 关联业务 ID |
| idempotency_key | string(150) | 可为空的幂等键；异步视频任务扣费和失败退款用于防止重复入账 |
| note | string(500) | 备注 |
| metadata | longtext | 流水扩展详情 JSON，如模型、接口、计费单位、操作人 |

后台积分调整的 `amount` 保存带符号的实际余额变化，`metadata` 同时保存变动前后余额、调整模式、目标余额、操作人和目标用户。

## credit_pricing 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uint | 主键 |
| tenant_id | uint | 租户 ID |
| model | string(100) | 模型名 |
| credits_per_unit | int | 按次计费的单次积分消耗；动态视频计费可为 0 |
| unit_type | enum(per_image/per_video/per_video_second/per_token) | 计费单位 |
| pricing_mode | enum(per_unit/video_dynamic) | 计费方式；`video_dynamic` 表示按视频秒数和分辨率动态计费 |
| pricing_rule | longtext | 动态计费规则 JSON，例如视频基础积分和各分辨率秒单价 |

该表是当前生成与计费链路使用的兼容投影。管理后台以 `model_pricing_rules` 为规范化写入入口，保存默认价或渠道模型覆盖价时在同一事务内刷新本表；不得直接用本表反向覆盖规范化规则。

## tenant_api_configs 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uint | 主键 |
| tenant_id | uint | 当前固定为默认租户 |
| base_url | string(500) | 上游 API 地址 |
| api_key | text | 加密后的上游 API Key |
| models / image_models / video_models / text_models / audio_models | longtext | 旧版模型与能力列表 JSON |
| model_routes | longtext | 旧版模型图片、视频接口路由 JSON |
| model_video_durations | longtext | 旧版视频时长映射 JSON |
| model_video_customizable | longtext | 旧版视频可配置状态映射 JSON |

v0.5 保留该表用于旧 `/api-config` 双读写。旧入口保存会在同一事务内更新本表和规范化模型目录，并返回弃用提示；启动时会为旧记录创建稳定兼容渠道，原样复制已加密 API Key。v0.6 改为只读，v0.7 移除旧业务入口后继续保留该表作为备份。

## channels 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uint | 主键 |
| name | string(100) | 渠道显示名称，带索引 |
| base_url | string(500) | 上游 API 基础地址 |
| api_key | string(500) | 加密后的上游 API Key；模型 JSON 输出中隐藏该字段 |
| enabled | bool | 渠道是否启用，默认 true，带索引 |
| video_api_standard | string(20) | 视频 API 标准：`default` / `binghuo`，默认 `default`；`binghuo` 会覆盖该渠道全部视频模型的模型级路由 |
| new_api_channel_id | int | 可为空，对应 new-api 的 channel_id |
| new_api_channel_id_val | string(100) | new-api 渠道人类可读映射名称 |
| metrics_base_url | VARCHAR(512) | NULL | 指标服务地址（为空则使用 base_url + /api） |
| remark | VARCHAR(500) | NULL | 管理员备注 |
| sync_status | string(20) | 模型同步状态：pending/syncing/success/failed |
| sync_error | string(500) | 最近一次同步错误信息 |
| synced_at | datetime | 可为空，最近一次成功同步时间 |
| config_revision | uint | 渠道协议与配置的乐观锁修订号，默认 1 |

API Key 仅用于后端代理调用，按 `API_KEY_ENCRYPTION_KEY` 配置加密存储，不应出现在 JSON 响应中。

## channel_models 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uint | 主键 |
| channel_id | uint | 所属渠道 ID，非空，带索引 |
| model_name | string(200) | 上游原始模型名，非空 |
| catalog_model_id | uint | 对应稳定公开模型目录 ID |
| upstream_model_id | string(200) | 可编辑的上游实际模型 ID |
| status | enum(draft/active/disabled) | 后台配置状态 |
| discovery_status | enum(present/missing) | 最近一次同步是否仍由上游返回 |
| last_discovered_at | datetime | 最近发现时间，可为空 |
| config_revision | uint | 单模型原子保存的乐观锁修订号 |
| legacy_unreviewed | bool | 升级保留可用但仍需管理员复核的旧模型标记 |
| capabilities | string(100) | 模型能力 JSON 数组，可包含 image/video/text/audio |
| enabled | bool | 渠道内模型是否启用，默认 true |
| image_generate_route | string(30) | 图片生成路由：auto/generations/edits/chat/banana |
| image_edit_route | string(30) | 图片编辑路由 |
| video_route | string(30) | 视频路由：auto/openai/veo_json/waninter/yijia/xai/newapi/seedance；渠道使用炳火标准时保留但暂不生效 |
| video_durations | string(200) | 视频时长 JSON 数组，例如 `[5,10]` |
| video_customizable | bool | 视频参数是否支持用户自定义，默认 false |
| video_custom_config | text | `video_route=custom` 时保存规范化的固定参数目录 JSON |
| sort_order | int | 前台展示排序，默认 0 |

`channel_id` 与 `model_name` 组成唯一约束 `idx_channel_model`，避免同一渠道重复记录同名模型。

`video_custom_config` 中只有 `images`、`input_reference`、`style_references`、`element_references`、`reference_images` 和 `input_video` 六个媒体角色可以设置 `required`。禁用的媒体角色统一规范化为 `required=false`；启用且 `required=true` 的角色必须在运行时提供至少一个有效素材，启用但 `required=false` 的空角色不会写入上游请求。时长、尺寸、参考图模式、音频和生成数量等标量或固定字段没有 `required` 语义。

## catalog_models 表

| 字段 | 类型 | 说明 |
|------|------|------|

一个公开模型可以由多个 `channel_models` 实现，上游模型 ID 或显示名称变化时不需要改写用户保存的公开身份。

## model_pricing_rules 表

| 字段 | 类型 | 说明 |
|------|------|------|
| tenant_id | uint | 当前配置所属租户 |

| scope | enum(default/implementation) | 全局默认价或渠道模型覆盖价 |

## model_config_audit_logs 表

保存模型服务敏感操作的脱敏前后快照，包含 `tenant_id`、`actor_user_id`、资源类型、资源 ID 和动作。API Key 不写入审计 JSON。

## model_config_migrations / model_config_migration_issues 表

`model_config_migrations` 按来源、来源 ID 和版本唯一登记兼容迁移状态与目标资源；`model_config_migration_issues` 记录无法安全推断的配置及原因。已完成且目标仍存在的启动迁移直接跳过，失败记录彼此隔离，不阻止其它旧配置迁移。

## generation_jobs 表

| 字段 | 类型 | 说明 |
|------|------|------|
| request_id | string(64) | 生成请求唯一 ID，也是扣款与退款幂等边界 |
| tenant_id / user_id | uint | 所属租户和用户 |
| capability | string(20) | image/video/text/audio |
| model_name | string(191) | 计费模型名快照 |
| auto_routing_pool_id | uint | 智能路由池 ID；直接渠道为 0 |
| channel_id / channel_model_id | uint | 已解析的物理渠道快照 |
| channel_name / channel_base_url | string | 请求时渠道信息快照 |
| video_route | string(50) | 请求时视频协议快照 |
| authorized_amount | int | 请求开始时预留的最高候选费用 |
| billing_amount | int | 最终物理渠道的实际结算费用 |
| spend_transaction_id | uint | 扣款流水 ID |
| settlement_transaction_id | uint | 预留差额退回流水 ID |
| refund_transaction_id | uint | 退款流水 ID |
| upstream_task_id | string(191) | 异步上游任务 ID |
| status | enum(reserved/pending/succeeded/refunded) | 计费生命周期状态 |
| failure_reason | string(500) | 退款或失败原因 |

生成前在一个事务中锁定积分账户、扣款、写入流水并创建 `generation_jobs`。同步上游失败按 `request_id` 幂等退款；异步失败按物理渠道快照和 `upstream_task_id` 查找原任务，不重新选路。

## auto_routing_pools 表

| 字段 | 类型 | 说明 |
|------|------|------|
| public_model_name | string(200) | 用户侧公开模型名，与能力组成唯一约束 |
| capability | string(20) | image/video/text/audio |
| contract_key | string(64) | 规范化协议合同的 SHA-256 指纹 |
| enabled | bool | 路由池是否对用户可用 |
| max_attempts | int | 单次请求最大物理候选尝试数，当前为 1 或 2 |

路由池由系统建议、SuperAdmin 确认创建。新池默认禁用，至少两个合同有效成员时才能启用。

## auto_routing_pool_members 表

| 字段 | 类型 | 说明 |
|------|------|------|
| pool_id | uint | 所属智能路由池 |
| channel_model_id | uint | 具体物理渠道模型，与 `pool_id` 组成唯一约束 |
| priority | int | 可靠性相同时使用的管理员优先级 |
| enabled | bool | 成员是否参与候选解析 |

成员不复制模型协议字段。运行时会用当前 `channel_models` 和 `channels` 重新计算合同；配置变化导致指纹不匹配时成员暂时失效，切回兼容配置后可恢复。管理员确认新合同建议时，成员替换与池合同更新在同一事务中完成，未变成员的优先级和启用状态保留，池自动关闭等待复核。

## generation_attempts 表

| 字段 | 类型 | 说明 |
|------|------|------|
| request_id / attempt_no | string / int | 用户请求和尝试序号，组成唯一约束 |
| pool_id | uint | 本次使用的智能路由池 |
| channel_id / channel_model_id | uint | 实际尝试的物理候选 |
| status_code | int | 上游 HTTP 状态码，网络错误为 0 |
| response_time_ms | int | 本次尝试耗时 |
| success | bool | 是否成功 |
| failure_category | string(30) | 归一化失败分类 |
| retryable | bool | 是否允许切换下一候选 |
| counts_for_health | bool | 是否计入 24 小时可靠性和熔断计算 |
| error_message | string(500) | 审计错误摘要 |

可靠性只统计真实生成尝试，使用 `(成功数 + 9) / (尝试数 + 10)` 平滑。五分钟内连续三次可重试失败会熔断两分钟，冷却后只允许一个半开探测。

## 数据库迁移

新增结构迁移使用嵌入式 Goose SQL。`00001_canvas_and_generation_jobs.sql` 负责画布复合唯一约束、文档版本字段和生成任务表；`00002_auto_routing_pools.sql` 增加智能路由池、成员、尝试审计及生成任务结算字段；`00003_model_service_catalog.sql` 建立规范化模型目录、协议、定价、修订与审计结构并投影已有渠道模型；`00004_legacy_api_config_compatibility.sql` 登记旧 `TenantApiConfig` 的应用级兼容迁移。应用启动时先执行现有表的兼容 `AutoMigrate`，再执行有版本的增量迁移，随后幂等处理待迁移旧配置。后续表会逐步移出 `AutoMigrate`，每个增量只允许新增新的迁移版本，不修改已经发布的迁移文件。

## 用户删除关系

管理员确认删除账号后，系统会在一个数据库事务中执行不可恢复的硬删除。删除顺序固定为目标积分账户下的 `credit_transactions`、`credit_accounts`、`canvas_projects`、`generation_records`、`recharge_orders`、`model_call_logs`，最后删除 `users` 记录；任一步失败都会回滚此前删除。租户配置、渠道和其它用户数据不属于账号删除范围。
