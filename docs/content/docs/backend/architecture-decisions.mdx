# 架构决策记录

## ADR-001 模型目录唯一事实来源

服务端模型配置以 `catalog_models`、`channels`、`channel_models`、`channel_model_operations`、`channel_protocol_defaults` 和 `model_pricing_rules` 为规范化事实来源，模型合并组、视频预设和智能路由池引用该目录。`credit_pricing` 仅保留为生成链路的兼容价格投影，不得反向覆盖规范化定价。

v0.5 期间旧 `TenantApiConfig` 保留双读写：旧入口保存时必须在同一事务内同步规范化目录，并返回弃用提示；启动迁移按迁移版本幂等执行。v0.6 将旧写入口改为只读拒绝，v0.7 确认无调用后移除旧接口，旧表继续作为只读备份。新功能不得从旧模型列表反推能力、协议或定价。

前端展示值可以暂时保留编码 key，但业务请求必须先通过目录 Map 解析为结构化 `ModelSelection`：物理模型使用 `channel_model_id`，智能路由使用 `routing_pool_id + model`，合并组使用 `channel_id + group_name`。请求链路不得仅凭 `channel_id=0 + model` 推断候选，也不得自行拆解显示字符串决定业务语义。

## ADR-002 协议由能力、操作和路由共同决定

模型名不是协议。请求规划器根据能力、生成或编辑操作和后台显式路由生成 method、path、Content-Type 与载荷。图片 `generations`、`edits`、`chat`、`banana` 和视频有限路由均使用集中枚举及校验。

登录用户生成与管理后台模型测试共享同一协议合同和黄金用例。模型配置中的 `route=auto` 仅表示“兼容默认”协议，不等于智能路由；任何新增特殊协议都必须新增适配器和测试，不能在页面或模型名判断中散落分支。

## ADR-003 先预留计费，再调用上游

每次收费生成创建唯一请求 ID。账户行锁、余额校验、扣款、支出流水和 `GenerationJob` 创建在一个事务中完成；预留失败时不得调用上游。同步失败按请求 ID 幂等退款，异步失败按原物理渠道快照和上游任务 ID 退款。

智能路由生成前按所有可用候选的最高费用预留一次，成功后按最终物理渠道结算并退回差额，全部失败全额退款。一个用户请求只创建一个 `GenerationJob` 和一笔预留流水。智能路由和合并组只在任务创建前选路；创建后轮询、日志、下载、成功确认和退款始终引用 `GenerationJob` 保存的物理渠道，不能重新路由。

## ADR-004 画布使用文档版本和乐观锁

无 `schemaVersion` 的旧画布定义为版本 1。每个版本只通过纯函数迁移到下一版本，禁止在组件中散落旧字段兜底。未知的未来版本不得被当前客户端降级保存。

云端身份是 `tenant_id + user_id + project_id`，`revision` 是并发保存边界。冲突返回最新云端版本，同时客户端保留本地副本。画布导出 envelope 保持 `version: 3`。模型 API 配置包的加密 envelope 保持 `version: 1`，当前内部 payload 为 `schema_version: 2`，导入器长期接受 payload v1；新增格式只能增加新版本解析器。

## ADR-005 智能路由必须显式确认

智能路由池按“公开模型名 + 能力”唯一，由系统按当前模型协议合同生成建议，SuperAdmin 确认后创建；同名模型不再自动聚合。模型配置变化不会改写路由池，只会让合同不匹配成员暂时失效并在后台提示。管理员通过新建议重新确认时，合同和候选在同一事务中更新，路由池自动关闭，检查后再手动启用。

运行时只在同一合同内选路。排序固定为熔断状态、24 小时平滑可靠性、管理员优先级、P95 延迟、当前请求价格和 `channel_model_id`。单次最多尝试两个候选，只有网络、超时、上游鉴权、限流和 5xx 可切换；参数错误、内容拒绝、计费和本地校验失败直接返回。

## ADR-006 模型配置以修订号原子保存

渠道默认协议与模型配置分别使用 `config_revision` 做乐观并发控制。单模型保存必须在一个事务内更新公开身份、上游模型 ID、操作合同、渠道定价覆盖、旧生成链路投影和脱敏审计；任一步失败都回滚整次保存。

新同步发现的模型保持 `draft` 且禁用，只有至少一个完整操作合同和对应有效定价时才能首次启用。迁移前已经启用的模型保留可用状态并标记 `legacy_unreviewed`，由管理员复核，不在升级时强制停用。同步未发现的模型只标记 `discovery_status=missing`，不删除配置。

## 分阶段实施边界

当前已建立质量门禁、结构化选择、图片请求规划器、事务化计费任务、画布迁移和首个 Goose 增量迁移。`GenerateService` 和画布页面仍是迁移期编排器，后续拆分必须以现有特征测试为约束逐步完成，禁止一次性重写。
